JScript

JScript was Microsoft's implementation of a scripting language for web pages. It was introduced in 1996 with Internet Explorer 3.0 and was largely compatible with Netscape's JavaScript. Microsoft developed JScript partly because "JavaScript" was a trademark associated with Netscape.

Although JScript and JavaScript were closely related, they were separate implementations. This meant that a script could behave differently depending on which browser was being used. This was particularly significant during the early development of the Web, when browsers did not always implement scripting features in the same way.

JScript and JavaScript

JScript JavaScript
Developed by Microsoft Originally developed by Netscape
Primarily associated with Internet Explorer Used across many browsers
Introduced in 1996 Introduced in 1995
Microsoft-specific implementation Eventually standardized through ECMAScript

Example of JScript

JScript used syntax that was very similar to JavaScript. For example, a simple script could display a message in the browser: 

<script>
var message = "Hello from JScript!";
alert(message);

The similarity between JScript and JavaScript meant that many simple scripts could work in both environments. However, differences between browser implementations could cause compatibility problems.

The Decline of JScript

As web standards became increasingly important, browser developers moved toward implementing standardized ECMAScript features rather than maintaining proprietary scripting dialects. JScript therefore became associated with legacy versions of Internet Explorer.

Microsoft eventually replaced Internet Explorer with Microsoft Edge, which uses modern web standards and does not use the traditional JScript engine for normal web development. JScript is therefore considered a legacy technology rather than a language used for modern web development.

Historical significance: JScript is an example of how competing browser implementations contributed to compatibility problems during the early history of the Web. The development and adoption of standards such as ECMAScript helped reduce these differences.

ECMAScript Features

ECMAScript is the standardized specification that defines the core features of JavaScript. It is developed and maintained by TC39, a technical committee of Ecma International. JavaScript implementations, such as those found in web browsers, follow the ECMAScript standard.

ECMAScript has evolved significantly over the years. One of its most important milestones was ECMAScript 2015 (ES6), which introduced many features that are now commonly used in modern JavaScript development. Since ES2016, new editions have generally been released on a yearly basis.

Evolution of ECMAScript

The following table presents some important ECMAScript editions and examples of the features they introduced:

Important Features

Let and Const

ECMAScript 2015 introduced let and const as block-scoped alternatives to var. A let variable can be reassigned, while a const variable cannot be reassigned after it has been initialized. 

let score = 80;
score = 90;

const name = "John";
Arrow Functions

Arrow functions provide a shorter syntax for writing functions. They are frequently used with array methods and callback functions. 

const numbers = [1, 2, 3];

const doubled = numbers.map(
number => number * 2
);
Destructuring

Destructuring makes it possible to extract values from arrays or objects and assign them directly to variables. This can make code shorter and easier to read. 

const student = {
name: "Maria",
major: "Computer Engineering"
};

const { name, major } = student;
Async and Await

ECMAScript 2017 introduced async and await, which provide a clearer way to work with asynchronous operations based on Promises. They are commonly used when retrieving data from servers or APIs. 

async function getData() {
const response = await fetch("/data");
return response.json();
}

Why ECMAScript Matters

The development of ECMAScript has helped JavaScript evolve from a relatively simple scripting language into a language used to build complex web applications and other software. Standardization also provides a common specification that different JavaScript implementations can follow.

Did you know? ECMAScript and JavaScript are closely related, but they are not exactly the same thing. ECMAScript defines the language standard, while JavaScript implementations follow that standard and may also provide additional features such as browser Web APIs.

IIFE (Immediately Invoked Function Expression)

An Immediately Invoked Function Expression (IIFE) is a JavaScript function that is defined and executed immediately. Unlike a normal function, an IIFE does not need to be called separately after it has been created.

IIFEs were commonly used in older JavaScript applications to create a private scope for variables. Before modern features such as let, const, and JavaScript modules became widely available, IIFEs provided a way to prevent variables from unnecessarily becoming accessible outside a particular section of code.

Basic Syntax

An IIFE is usually written by placing a function expression inside parentheses and immediately invoking it with another pair of parentheses: 

(function () {
console.log("This function runs immediately!");

})();

The final () calls the function as soon as it has been created. The surrounding parentheses make the function an expression rather than a normal function declaration.

Using a Private Variable

One important use of IIFEs was creating variables that could only be accessed from inside the function. This helped prevent accidental conflicts with variables in other parts of a program. 

(function () {
const message = "Private information";

console.log(message);

})();

In this example, message exists only inside the IIFE. Code outside the function cannot directly access it.

Passing Arguments

An IIFE can also receive arguments just like a regular function. This allows data to be passed into its private scope. 

(function (name) {
console.log("Hello, " + name);

})("Hady");

Why Were IIFEs Important?

IIFEs became particularly useful before JavaScript had modern module systems and block-scoped declarations. They allowed developers to isolate variables and create a form of private scope, which reduced the possibility of naming conflicts in larger scripts.

Summary of IIFE Characteristics

Characteristic Description
Execution The function runs immediately after it is created.
Scope Variables can be kept inside the function's scope.
Arguments An IIFE can receive arguments like a normal function.
Common use Older scripts, initialization code, and avoiding global variables.

IIFEs in Modern JavaScript

IIFEs are still valid JavaScript, but they are less necessary in modern applications. Features such as let and const, as well as ES modules, provide cleaner ways to control scope and organize code.

Key idea: An IIFE combines two actions: creating a function expression and immediately calling that function. Its main historical advantage was providing an isolated scope for variables.

Variadic Functions and Rest Parameter Functions

A variadic function is a function that can accept a variable number of arguments. Instead of requiring a fixed number of parameters, the function can process as many arguments as are provided when it is called.

JavaScript has traditionally supported functions with a variable number of arguments through the special arguments object. ECMAScript 2015 introduced the rest parameter, which provides a clearer and more convenient way to collect multiple arguments into an array.

Traditional Approach

Before rest parameters, developers could use the arguments object to access all arguments passed to a function. 

function sum() {
let total = 0;

for (let i = 0; i < arguments.length; i++) {
    total += arguments[i];
}

return total;

}

console.log(sum(2, 4, 6));

In this example, the function does not define any parameters, but it can still receive and process three arguments. The arguments object contains the values passed to the function.

Rest Parameters

ECMAScript 2015 introduced the rest parameter syntax .... It collects all remaining arguments into a real array, making them easier to work with. 

function sum(...numbers) {
return numbers.reduce(
    (total, number) => total + number,
    0
);

}

console.log(sum(2, 4, 6, 8));

Here, numbers becomes an array containing all the arguments passed to the function. The same function can therefore accept two, four, or many more numbers without changing its definition.

Fixed and Variable Parameters

A rest parameter can also be combined with regular parameters. This is useful when a function requires some information but can accept additional values. 

function introduce(name, ...skills) {
console.log(name);
console.log(skills);

}

introduce(
"Pascal",
"Python",
"JavaScript",
"SQL"
);

In this example, name receives the first argument, while all remaining arguments are collected inside the skills array.

Key Differences

Arguments Object vs. Rest Parameters
Feature arguments Rest Parameter
Introduced Early JavaScript ECMAScript 2015
Syntax arguments ...parameters
Data type Array-like object Actual Array
Readability More verbose More concise and explicit
Common use Legacy JavaScript code Modern JavaScript

Why Are Rest Parameters Useful?

Rest parameters make variadic functions easier to write and understand. They are especially useful for functions that need to process an unknown number of values, such as mathematical calculations, combining lists, or handling optional arguments.

Key idea: The rest parameter ... collects multiple arguments into an array. It is called "rest" because it represents the remaining arguments after any regular parameters.
