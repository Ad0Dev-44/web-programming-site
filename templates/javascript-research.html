JScript

JScript was Microsoft's implementation of a scripting language for web pages. It was introduced in 1996 with Internet Explorer 3.0 and was largely compatible with Netscape's JavaScript. Because the two were separate implementations, the same script could behave differently depending on the browser.

JScript and JavaScript

JScript JavaScript
Developed by Microsoft Netscape
Introduced 1996 1995
Used in Mainly Internet Explorer Many browsers
Standard Microsoft-specific implementation Standardized as ECMAScript

The decline of JScript

As browsers moved toward the ECMAScript standard, JScript became tied to legacy versions of Internet Explorer. Microsoft Edge uses modern web standards, so JScript is now considered a legacy technology.

Historical significance: JScript shows how competing browser implementations caused compatibility problems, which standards such as ECMAScript later reduced.

ECMAScript Features

ECMAScript is the standard that defines the core features of JavaScript. It is maintained by TC39, a committee of Ecma International, and browsers follow it. A major milestone was ECMAScript 2015 (ES6), and new editions have been released yearly since ES2016.

Evolution of ECMAScript

Version Year Notable features
ES5 2009 Strict mode, JSON support, array methods
ES2015 (ES6) 2015 let, const, arrow functions, classes, modules, promises, destructuring
ES2017 2017 async/await, Object.values()
ES2020 2020 Optional chaining, nullish coalescing, BigInt
ES2022 2022 Private class fields, top-level await, Object.hasOwn()
ES2025 2025 Iterator helpers, RegExp.escape(), Promise.try()

Important features

let and const are block-scoped alternatives to var. Arrow functions give a shorter function syntax, destructuring extracts values from objects or arrays, and async/await makes Promise-based code easier to read. 

let score = 80;                              // can be reassigned
const name = "John";                         // cannot be reassigned

const doubled = [1, 2, 3].map(n => n * 2);   // arrow function

const { major } = { major: "Computer Engineering" };   // destructuring

async function getData() {
  const response = await fetch("/data");     // async / await
  return response.json();
}
Did you know? ECMAScript is the language standard, while JavaScript implementations follow it and may add extras such as browser Web APIs.

IIFE (Immediately Invoked Function Expression)

An IIFE is a function that is defined and executed immediately, without a separate call. It was commonly used in older code to create a private scope, so variables would not leak into the global scope before let, const and modules existed.

Syntax

The function is wrapped in parentheses, which makes it an expression, and is then called with a second pair of parentheses. It can also receive arguments. 

(function (name) {
  const message = "Hello, " + name;   // private: not visible outside
  console.log(message);
})("Hady");

IIFEs today

IIFEs are still valid JavaScript, but block scope (let and const) and ES modules now handle most of what they were used for.

Key idea: An IIFE creates a function expression and calls it at once, giving its variables an isolated scope.

Variadic Functions and Rest Parameter Functions

A variadic function accepts a variable number of arguments. JavaScript traditionally did this with the arguments object, and ECMAScript 2015 added the rest parameter (...), which collects the arguments into a real array.

arguments vs rest parameter

The arguments object is array-like but not a real array. A rest parameter is a true array and can follow regular parameters, collecting only the remaining arguments. 

function sumOld() {                    // traditional
  let total = 0;
  for (let i = 0; i < arguments.length; i++) total += arguments[i];
  return total;
}

function sum(...numbers) {             // rest parameter
  return numbers.reduce((total, n) => total + n, 0);
}

function introduce(name, ...skills) {  // fixed + variable parameters
  console.log(name, skills);
}

sum(2, 4, 6, 8);                       // 20
introduce("Pascal", "Python", "SQL");  // Pascal ["Python", "SQL"]

Key differences

arguments Rest parameter
Introduced Early JavaScript ECMAScript 2015
Data type Array-like object Real array
Common use Legacy code Modern code
Key idea: The rest parameter is called "rest" because it holds the remaining arguments after any regular parameters.

NodeList vs HTMLCollection

Both are array-like objects that hold DOM nodes. You can read .length and use an index, but neither is a real array. They differ in what they contain, how they update, and which methods they offer.

HTMLCollection

Contains elements only and is always live: when the DOM changes, the collection updates itself. It has no forEach, so convert it with Array.from() to loop.

const items = document.getElementsByClassName("item"); // HTMLCollection
const kids  = document.body.children;                   // HTMLCollection
items.namedItem("first");                               // lookup by id or name

NodeList

Can contain any node type (elements, text, comments). It is static when returned by querySelectorAll() and live when returned by childNodes. It supports forEach, entries, keys and values.

const list  = document.querySelectorAll(".item"); // static NodeList
const nodes = document.body.childNodes;           // live NodeList
list.forEach(el => console.log(el.textContent));

Map in JavaScript

A Map stores key-value pairs and remembers the order in which keys were inserted. Unlike a plain object, its keys can be any value: strings, numbers, objects, even functions.

Creating and using a Map

const scores = new Map();
scores.set("ana", 90);
scores.set("omar", 75).set("lina", 82); // set() is chainable

scores.get("omar");   // 75
scores.has("ana");    // true
scores.delete("lina");
scores.size;          // 2 (a property, not a method)
scores.clear();       // remove everything

// or build it from an array of [key, value] pairs
const m = new Map([["a", 1], ["b", 2]]);

Looping

for (const [key, value] of m) console.log(key, value);
m.forEach((value, key) => console.log(key, value));
[...m.keys()];     // ["a", "b"]
[...m.values()];   // [1, 2]
[...m.entries()];  // [["a", 1], ["b", 2]]

Iteration always follows insertion order.

localStorage in JavaScript

localStorage is part of the Web Storage API. It lets a page save data in the browser as key-value pairs. The data has no expiry date, so it is still there after the tab or the browser is closed. Each origin (protocol, domain and port) gets its own storage of about 5 MB.

Basic methods

Use setItem() to save a value and getItem() to read it back. If a key does not exist, getItem() returns null. 

localStorage.setItem("theme", "dark");
localStorage.getItem("theme");      // "dark"
localStorage.getItem("missing");    // null
localStorage.removeItem("theme");   // delete one key
localStorage.length;                // number of stored keys
localStorage.clear();               // delete everything

Storing objects and arrays

localStorage can only store strings. A number such as 5 is saved as "5". To store an object or an array, convert it with JSON.stringify() and convert it back with JSON.parse(). 

const student = { name: "Maria", year: 4 };
localStorage.setItem("student", JSON.stringify(student));

const saved = JSON.parse(localStorage.getItem("student"));
console.log(saved.name);            // "Maria"

localStorage vs sessionStorage vs cookies

localStorage sessionStorage Cookies
Lifetime Until deleted Until the tab is closed Until the expiry date
Capacity About 5 MB About 5 MB About 4 KB
Sent to the server No No Yes, with every request
Shared between tabs Yes (same origin) No (one tab only) Yes (same site)

Limitations

Any JavaScript running on the page can read localStorage, so it should never hold passwords or login tokens. It is also synchronous, so saving large amounts of data can slow the page down, and it may be unavailable if the user blocks storage in their browser.

Key idea: localStorage is a simple way to remember small, non-sensitive data such as a theme choice or a draft, and it works without a server. It always stores strings.
